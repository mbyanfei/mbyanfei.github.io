Turn an Old NAS into a Secure Personal Cloud & AI Lab

Use the NAS for what it is uniquely good at—private storage, family photos, dynamic applications, and personal AI—while leaving public static publishing on GitHub Pages or another managed edge platform.

Public static sitesKeep on GitHub Pages / Cloudflare Pages.
Private files & photosNAS + Immich + encrypted remote access.
Apps & AI experimentsContainers on NAS, or NAS + separate compute node.

Executive recommendation

Do not turn the NAS into a generic Internet-facing server. Treat it as a private data platform and selectively publish only specific applications. This sharply reduces the attack surface while still giving you permanent URLs, remote family photo access, APIs, databases, and AI capabilities.

Photo platform: start with Immich

Why it fits

  • Google Photos-like timeline and mobile experience.
  • Family albums and sharing links.
  • Face recognition and semantic image search.
  • Can index an existing library instead of forcing a full reorganization.

Important safety choice

Initially mount your existing photo archive into the application read-only. Let Immich create its own database, thumbnails, ML indexes, and application-managed data separately.

/photos/originals      # existing master archive
/photos/immich         # Immich-managed data
/apps/immich           # compose/config
/backups               # independent backups

# Conceptual mount
/photos/originals:/photos:ro

Do you need a static IP?

No—not with the recommended architecture. Cloudflare Tunnel creates an outbound connection from your home network to Cloudflare. Your ISP can change your residential IP and your public hostname can remain stable.

Traditional dynamic DNS and port forwarding are still possible, but they create more operational and security work. They are not the default recommendation here.

Nginx, PostgreSQL and Redis

Nginx

You may not need it initially. Cloudflare Tunnel can route hostnames directly to local application ports. If you later want a local reverse proxy, Nginx is fine; Caddy is attractive for a small home environment because HTTPS configuration is simpler.

PostgreSQL / Redis

Do not install one giant shared Postgres or Redis instance just because you can. Prefer application-scoped containers and networks. Immich's deployment already includes the supporting services it needs.

Baseline hardening checklist

  • Update NAS OS and packages before exposing anything.
  • Check SMART health on every disk.
  • Strong unique passwords and MFA where supported.
  • Disable or rename default administrator accounts where possible.
  • No public SMB, SSH, Postgres, Redis, or NAS admin ports.
  • Tailscale for private administration.
  • Cloudflare Tunnel for intentionally published services.
  • Separate containers and networks per application.
  • Read-only mount for irreplaceable master photo archives.
  • Never give ordinary application containers the Docker socket.
  • Keep credentials outside Git repositories.
  • Enable snapshots.
  • Use a UPS if the NAS contains important data.
  • Maintain an independent second backup.
  • Keep an offsite copy of irreplaceable photos/documents.
  • Test restore procedures periodically.

RAID is availability, not backup. It can help survive a disk failure; it does not protect you from deletion, ransomware, corrupted data, bad upgrades, theft, fire, or catastrophic hardware failure.

AI introduces a new trust boundary

An AI process with read + write + shell + Internet access is effectively a privileged user. The risk is no longer only “can a hacker reach my files?” but also “what can an agent read, modify, execute, or send elsewhere?”

Personal AI container

READ:
  /photos:ro
  /documents:ro

WRITE:
  /ai-index
  /ai-cache

NO ACCESS:
  NAS admin
  backup repository
  Docker socket
  SSH keys

Default AI permissions to read-only. Give write access only to dedicated working/index directories. Treat external model APIs as data egress and decide explicitly what is allowed to leave your home network.

Older NAS + separate AI compute is often better

Many older NAS devices are excellent storage servers and mediocre AI machines. If yours has limited RAM or an older ARM/Intel CPU, keep storage on the NAS and add a separate Mini PC, NUC, Mac mini, or GPU machine later.

NAS = storage, snapshots, backups

AI compute node = embeddings, OCR, transcription, local LLM

NAS ←── 2.5/10 GbE ──→ AI compute

Recommended rollout

1

Resurrect and protect

Identify model/CPU/RAM, check drives and RAID, update the NAS, and make an independent backup before experimenting.

2

Private remote access

Install Tailscale and confirm you can securely administer the NAS without opening router ports.

3

Deploy Immich

Use containers, start with a subset of photos, then index the master library read-only.

4

Publish selectively

Use your own domain and Cloudflare Tunnel for selected apps such as photos.example.com.

5

Add AI services

Build personal search/RAG/media intelligence with constrained permissions; add a separate compute node if the NAS is too weak.

Next hardware check

The exact recommendation now depends on the NAS model. Record the brand/model, CPU, RAM, number and size of drives, RAID type, available capacity, network speed, and whether Docker/Container Manager is supported. That determines whether Immich and AI can run directly on the NAS or whether the NAS should remain primarily the storage tier.
