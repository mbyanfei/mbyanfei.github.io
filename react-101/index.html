React 101: Build the same portal twice

Learn React by comparing plain HTML and JavaScript with a React application. Designed for engineers working with AI-generated frontend code.

Public training demo with fictional applications only. Not affiliated with or connected to BMO.
01. HTML + JavaScript ↗No build step. Open the live app and trace its manual DOM updates.02. React ↗Same interface, React components and state. Hosted code loads React via public CDN.

What to compare

Both apps have four teams, eight fictional application cards, search, team filtering and a favorites-only toggle. Use the same interactions in both and notice how each responds.

ConcernPlain JavaScriptReact
Changing a filterUpdate a variable and manually call render()Call a state setter; React updates the view
Application cardsCreate and attach DOM elementsReuse the AppCard component
FavoritesMutate a Set, then rerenderCreate a new Set in a state setter
Growing complexityYou coordinate updatesComponent + state model coordinates updates
DeploymentServe files directlyNormally build with Vite, then serve static assets

Five short lessons

  1. Components and JSX: find Portal and AppCard in the downloadable Vite source. Understand props.
  2. State and events: change team, search and favorites. Compare useState to ordinary variables.
  3. Derived data: trace filtered apps and the number of search results. useMemo is optional here.
  4. APIs: replace the fake catalog with a local JSON mock. Handle loading, errors and empty results.
  5. Build and deploy: run npm install, npm run dev and npm run build in the Vite source directory. Serve dist/ using Nginx or any static web server.

Recommended hands-on exercise

Add a Reset filters button to both apps. Then add a fictional application under QAS. You'll discover exactly what React abstracts and what plain JavaScript requires you to manage.

Important deployment distinction

The live React page uses browser-ready JavaScript and loads React from a public CDN to work on ordinary GitHub Pages. The downloadable source includes real React JSX + Vite. A standard Vite production build bundles the app into dist/. Neither approach needs a running Node.js server once deployed.
