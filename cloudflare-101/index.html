Mental model first

What is Cloudflare?

Cloudflare is a global front door for Internet applications: DNS, CDN, security, traffic routing, Zero Trust and increasingly application compute and storage — delivered from a worldwide edge network.

The shortest useful mental model

Think of Cloudflare as a globally distributed NGINX + security gateway + DNS + CDN + edge compute platform sitting between users and your applications.

User ↓ Cloudflare global edge ├─ DNS ├─ TLS / HTTPS ├─ CDN / cache ├─ DDoS protection ├─ WAF ├─ bot / rate limiting ├─ Zero Trust ├─ load balancing └─ edge / serverless code ↓ Your origin NGINX / AWS / Azure / on-prem / API

Cloudflare is not simply “another AWS”

Cloudflare started as the intelligent global layer in front of applications and infrastructure. It has gradually expanded inward until it can now host more of the application itself.

Your NGINX server does not necessarily disappear. Cloudflare can sit in front of it and handle Internet-facing concerns globally, while NGINX continues to reverse-proxy and route traffic inside your environment.

Traditional internal model

Browser → corporate network/LB → NGINX → oauth2-proxy → React/FastAPI

Cloudflare front-door model

Browser → Cloudflare global edge → NGINX/origin → React/FastAPI

Cloudflare can also go further: static frontend, Worker APIs, object storage, SQL and key/value data can all run on Cloudflare's platform without a conventional app server.

Who are the alternatives?

There is no perfect one-to-one competitor because Cloudflare spans several markets. The correct alternative depends on which Cloudflare function you are replacing.

Closest broad competitor

Akamai

Global CDN, edge delivery, DDoS, WAF, API security and enterprise edge services. This is the cleanest traditional Cloudflare comparison.

Developer edge

Fastly

Strong CDN, programmable edge, caching and security. Typically narrower than Cloudflare but technically sophisticated.

Hyperscaler

AWS

Assemble Route 53 + CloudFront + WAF + Shield + Lambda@Edge + S3 and other services. Much broader behind the edge, but less unified.

Microsoft enterprise

Azure

Azure Front Door provides global routing, CDN, TLS and WAF. Strong choice for Azure-heavy enterprises.

Google cloud

GCP

Cloud DNS + Cloud CDN + global load balancing + Cloud Armor + Cloud Run/Functions.

App hosting

Vercel / Netlify

Overlap mainly with application deployment and frontend hosting. Vercel is especially strong for Next.js.

Zero Trust / SASE

Zscaler / Netskope / Palo Alto

Compete primarily with Cloudflare's enterprise security and Zero Trust portfolio, not the full platform.

Reverse proxy / ADC

NGINX / F5 / HAProxy

Compete with parts of Cloudflare's routing, TLS and load-balancing capabilities, but you operate them yourself.

The NGINX distinction

NGINX is software you operate. Cloudflare is a global network someone else operates for you. This is the most important architectural difference.

The useful one-sentence distinction

AWS, Azure and GCP are huge clouds containing thousands of infrastructure services; Cloudflare is becoming an application cloud built outward from the Internet edge.

For learning, build one small site through this sequence: static page → DNS/CDN → Worker API → R2/KV/D1 → Access. That connects NGINX, reverse proxy, TLS, OAuth, Zero Trust, DNS, CDN, API gateways and serverless compute into one coherent architecture.
