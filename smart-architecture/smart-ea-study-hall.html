SMART Access Architecture

Proposed routing and security model for SMART UI and PET-to-SMART integration. The design separates internal browser access from governed system-to-system API access.

SMART UI Path

Browser → nginx → SMART API

SMART UI is an internal browser application. The browser connects to the SMART application ingress, where nginx serves the UI and reverse-proxies application API calls.

HTTPS / TLS terminates at nginx for the browser-facing connection
Design intent: SMART UI traffic does not need to traverse the enterprise API Gateway.
PET Integration Path

PET → cNLB → API Gateway/APIC → SMART

PET is a separate application consumer. PET enters through the governed enterprise API path rather than addressing the SMART application server directly.

OAuth bearer token is validated at the enterprise API enforcement point
Design intent: API Gateway/APIC provides centralized API policy enforcement and token validation for PET.
Security Model

TLS is hop-by-hop; OAuth protects the application request

The logical PET request may cross several infrastructure components, but this is not one continuous TLS tunnel. Each connection can terminate TLS and establish a new downstream TLS session.

Architecture Summary

Proposed target state

SMART UIBrowser traffic enters through nginx, which serves the UI and proxies to the SMART API.
PET IntegrationPET enters through cNLB and API Gateway/APIC before reaching SMART.
Security SeparationTLS secures each transport hop; OAuth authenticates and authorizes the PET application request.
EA Confirmation Points

Items to confirm in Study Hall

  • Confirm whether PET → cNLB uses standard one-way TLS or mutual TLS.
  • Confirm the formal TLS termination point at enterprise ingress.
  • Confirm whether API Gateway → SMART remains TLS-encrypted to nginx.
  • Confirm whether API Gateway routes to nginx or directly to the SMART API service endpoint.
  • Confirm the production identity provider and client-credentials pattern for PET.
These are implementation confirmation points; they do not change the core separation between SMART UI ingress through nginx and PET ingress through the enterprise API Gateway path.
