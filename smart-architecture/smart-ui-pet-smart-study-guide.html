SMART UI vs PET → SMART: Routing, Authentication & TLS

EA Study Hall summary: separate the browser/UI path from the system-to-system PET integration path. The main design principle is simple: SMART UI enters through nginx; PET enters through the enterprise API gateway path.

Path 1 — SMART UI

Browser → nginx → SMART API

The normal SMART UI browser path should not traverse the enterprise API Gateway.

EA takeaway: nginx is the browser-facing ingress and reverse proxy for SMART UI. It serves the UI and can proxy /api/* calls to the SMART API.

TLS

  • Browser establishes HTTPS to nginx.
  • nginx presents the SMART server certificate.
  • The browser validates hostname, trust chain, and expiry.
  • nginx → SMART API is a separate internal hop; TLS there depends on enterprise policy and deployment topology.
Path 2 — PET Integration

PET → cNLB → API Gateway/APIC → SMART

PET is a separate application and should enter through the governed enterprise API path rather than calling nginx directly.

EA takeaway: PET does not bypass the gateway. The gateway is the enterprise enforcement point for API policy and OAuth token validation.

Authentication

  • PET backend authenticates as an application using OAuth 2.0 client credentials.
  • Identity provider issues a short-lived access token.
  • PET sends Authorization: Bearer <access_token>.
  • API Gateway/APIC validates token signature, issuer, audience, expiry, and required scope/role.
TLS Termination — Important Distinction

Do not think of PET → SMART as one continuous TLS tunnel

Each infrastructure hop can create a new TLS session. TLS termination therefore happens per connection, not once for the entire logical request path.

One-Slide Summary

What EA should remember

  • SMART UI: Browser → nginx → SMART API.
  • PET integration: PET → cNLB → API Gateway/APIC → SMART API.
  • UI traffic does not need to traverse API Gateway.
  • PET should not call nginx directly as an integration endpoint.
  • TLS is hop-by-hop. Each new connection can terminate and establish a fresh TLS session.
  • OAuth is separate from TLS. TLS secures the connection; OAuth authenticates/authorizes the application request.
Suggested Study-Hall Talk Track
30-second explanation

“We have two distinct ingress patterns. SMART UI is an internal browser application, so the browser terminates HTTPS at nginx and nginx reverse-proxies to the SMART API. PET is a separate system consumer, so it enters through the governed enterprise API path: cNLB, API Gateway/APIC, then SMART. PET obtains a short-lived OAuth access token and the gateway validates it. TLS is hop-by-hop; cNLB, the gateway, and nginx may each terminate one TLS session and create another downstream.”
