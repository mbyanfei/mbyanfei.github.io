Prefect Control Plane, Workers & SSO Bypass

A practical mental model for Prefect API server, deployments, work pools, work queues, workers, polling, logs, and machine-safe access behind SSO.

1. The simplest mental model

Prefect server = control plane. It stores deployments, schedules, flow-run state, orchestration metadata, and logs.

Prefect worker = execution agent. It runs in the environment where your Python code should actually execute.

PREFECT CONTROL PLANE API Server | +-----------------+-----------------+ | | | Deployments Schedules Flow Runs | | +---------------- Work Pool --------+ | Work Queue | | worker polls v EXECUTION ENVIRONMENT Worker | launches job | v Python Flow

2. Core concepts

ConceptWhat it isWhere it lives

DeploymentA runnable configuration of a flow: parameters, schedule, pool/queue, code location, execution settings.Prefect server
ScheduleDefines when a deployment should create runs.Prefect server

Work PoolA logical execution target / category for runs.Prefect server
Work QueueA queue inside a work pool used for routing and priority.Prefect server
WorkerA running process that polls Prefect and launches work.Execution machine

3. Why the worker polls

The Prefect server knows what should run and when. The worker knows where and how to execute it.

Server: schedule reached ↓ create Flow Run ↓ mark run Scheduled ↓ place it in logical pool/queue Worker: poll API ↓ find scheduled run ↓ claim it ↓ launch process ↓ execute Python code

This pull model avoids the server needing inbound administrative access to every execution machine. The worker only needs outbound HTTPS connectivity to the Prefect API.

Key distinction: the server triggers the orchestration event; the worker performs the physical execution.

4. Why interactive SSO can break workers

Putting the Prefect API behind browser-oriented SSO can cause a worker API request to receive an OAuth redirect instead of JSON.

Worker ↓ Prefect API URL ↓ Nginx ↓ OAuth2 Proxy ↓ "Please sign in" ↓ Worker cannot click / MFA / browser-login ↓ API call fails

Browser users and machine clients have different authentication needs. A background worker should not be expected to complete a human login flow.

5. Practical bypass pattern

One pragmatic internal pattern is:

  • Keep browser routes protected by OAuth2 / Entra SSO.
  • Keep the raw Prefect backend bound to loopback.
  • Allow only an approved worker source to access /api/ without interactive SSO.
  • Make sure the worker connects directly rather than through a shared corporate proxy.
location ^~ /api/ {
    satisfy any;

    allow <TRUSTED_WORKER_IP>/32;
    deny all;

    auth_request /oauth2/auth;
    error_page 401 = @oauth2_signin;

    proxy_pass http://127.0.0.1:4200;
}

The important directive is:

satisfy any;

It means the request is allowed when either the network allow rule succeeds or the OAuth authentication succeeds.

6. Why NO_PROXY matters

If the execution host is configured to use a corporate HTTP/HTTPS proxy, Nginx may see the proxy's IP rather than the worker's IP.

Without NO_PROXY: Worker → Shared Proxy → Nginx sees proxy IP With NO_PROXY: Worker ───────────────→ Nginx sees worker IP

NO_PROXY does not itself disable authentication. It changes the network path so the trusted source identity can be evaluated correctly.

NO_PROXY=prefect.example.internal,10.0.0.10

7. Where logs live

The flow/task code executes on the worker machine, but Prefect-native logs and state are sent back through the Prefect API and stored with orchestration metadata on the server side.

Worker machine | | flow executes | log.info(...) v Prefect client | | API calls v Prefect server | +--> flow/task logs +--> run state +--> orchestration metadata | v Prefect UI

Separate from this, the worker process also has local console/service logs, and the Prefect server/Nginx/OAuth proxy each have their own infrastructure logs.

8. Container persistence lesson

If self-hosted Prefect uses SQLite inside a container, stopping the container does not delete the database. Deleting and recreating the container can.

Persist Prefect's home directory outside the container:

-v /persistent/prefect-data:/root/.prefect:Z
For production-grade resilience or higher concurrency, PostgreSQL is generally a better metadata database than container-local SQLite.

10. The architecture rule worth remembering

Browser SSO asks: “Who is this human?”

Machine authentication asks: “Which approved workload is making this request?”
